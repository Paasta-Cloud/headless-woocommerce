# خانه‌چین: نمونهٔ فروشگاه فارسی Headless WooCommerce

یک نمونهٔ مستقل و قابل‌تغییر از فروشگاه فارسی RTL با Next.js و WooCommerce Store API. این پروژه وابسته به کد داخلی پاستا یا قالب وردپرس نیست. صفحهٔ محصول، سبد، علاقه‌مندی‌ها، راهنمای خرید، حساب و صورت‌حساب دارد. پرداخت در محل و درگاه زیبال را پشتیبانی می‌کند؛ زیبال در دموی فعلی فقط آزمایشی است.

دموی عمومی: [headless-woocommerce-demo.neda1.paasta.app](https://headless-woocommerce-demo.neda1.paasta.app). این دمو به یک نصب واقعی ووکامرس روی وردپرس اکو پاستا متصل است. مجموعهٔ مرجع شامل ۳۲ کالای صنایع‌دستی با قیمت تومانی است. این کالاها برای نمایش وارد شده‌اند و تا تعیین موجودی واقعی، ناموجود هستند.

## راه‌اندازی

### ظاهر صنایع‌دستی و محصولات مرجع

صفحهٔ اصلی با مرجع تصویری `https://dinaha.i-design.ir/` بازطراحی شده است. بنرهای این نسخه از میزبان مرجع بارگذاری می‌شوند و زیر مجوز MIT کد پروژه قرار نمی‌گیرند؛ برای توزیع مستقل، دارایی‌های دارای مجوز خود را جایگزین کنید.

دستور `node scripts/reference-products.mjs > reference-products.csv` فایل استاندارد ورود ووکامرس از نام، قیمت تومانی، دسته و تصویر عمومی کالاهای مرجع می‌سازد. در فروشگاه مقصد با واحد تومان، آن را از بخش محصولات ← درون‌ریزی وارد کنید؛ گزینهٔ به‌روزرسانی محصولات موجود، SKU ثابت را برای جلوگیری از تکرار استفاده می‌کند. کالاهای مرجع ابتدا ناموجود هستند تا موجودی واقعی توسط فروشنده مشخص شود. کاتالوگ فعلی حذف یا جایگزین نمی‌شود.


```bash
git clone https://github.com/Paasta-Cloud/headless-woocommerce.git
cd headless-woocommerce
npm install
npm run dev
```

فایل `.env` فقط مقدار غیرمحرمانهٔ `WOOCOMMERCE_URL=demo` دارد تا استقرار Git روی پاستا در حالت نمایشی کار کند. نام و قیمت‌های این حالت ساختگی‌اند. برای دریافت محصولات واقعی، `.env.example` را به `.env.local` کپی کنید و `WOOCOMMERCE_URL` را به نشانی HTTPS سایت وردپرس خود تنظیم کنید؛ در پاستا همین متغیر را در تنظیمات سرویس تغییر دهید. رمز و کلید را هرگز در `.env` عمومی ثبت نکنید. ویترین برای خواندن Store API عمومی به کلید مدیریتی نیاز ندارد.

برای استقرار روی پاستا، بعد از تنظیم نشانی ووکامرس در متغیر محیطی پروژه، از مسیر Git یا CLI استفاده کنید. ساخت پروژه و سرویس ممکن است هزینه داشته باشد؛ پلن و مبلغ را پیش از تأیید بررسی کنید. دستورهای پایه:

```bash
npm test
npm run build
paasta deploy --git https://github.com/Paasta-Cloud/headless-woocommerce.git --name my-store
```

برای واردکردن از خط فرمان، `php scripts/import-reference-products.php /path/to/wordpress reference-products.csv` را با هویت سیستم‌عامل همان سایت اجرا کنید، نه کاربر root. اجرای دوباره محصولات موجود را تغییر نمی‌دهد و فقط تصویر ناقص را تکمیل می‌کند. تصاویر محصول در رسانهٔ وردپرس ذخیره می‌شوند.

متغیر اختیاری `WOOCOMMERCE_CATEGORY_ID` ویترین را به یک دسته محدود می‌کند؛ در دموی فعلی دستهٔ مجموعهٔ مرجع انتخاب شده است. این فیلتر مرز مجوز خرید نیست. کاتالوگ تا ۱۰۰۰ محصول را با خواندن همهٔ صفحه‌های Store API دریافت می‌کند؛ برای فروشگاه بزرگ‌تر باید جست‌وجو و صفحه‌بندی سمت سرور پیاده شود.

## وضعیت قابلیت‌ها

- کاتالوگ، جست‌وجوی محلی و فیلتر دسته‌بندی کار می‌کنند. بدون تنظیم ووکامرس، سبد نمایشی و دادهٔ ساختگی نمایش داده می‌شود.
- مرتب‌سازی کالاها بر اساس قیمت یا جدیدترین‌ها و فهرست علاقه‌مندی‌ها در خود فرانت‌اند انجام می‌شود. علاقه‌مندی‌ها فقط در مرورگر ذخیره می‌شوند و به حساب وردپرس وابسته نیستند.
- صفحهٔ `/guide` محتوای راهنمای خرید و نشانی دریافت را از `lib/storefront-config.js` می‌خواند. نام فروشگاه، ناوبری و محتوای عمومی را می‌توانید بدون تغییر قالب یا برگه‌های وردپرس شخصی‌سازی کنید.
- در حالت اتصال، فهرست محصولات، تصویر، دسته‌بندی و قیمت از `/wp-json/wc/store/v1/products` دریافت می‌شود.
- هر کالا صفحهٔ مستقل دارد. در حالت اتصال، افزودن و تغییر تعداد کالا از Store API ووکامرس انجام می‌شود. Cart Token فقط در کوکی HttpOnly فرانت‌اند نگهداری می‌شود و سبد پس از بارگذاری دوباره بازیابی می‌شود. کالاهای متغیر (variable) با انتخاب گزینه‌ها (رنگ، اندازه و…) قابل افزودن‌اند: گزینه‌های ممکن، قیمت و موجودی هر واریانت از Store API خوانده می‌شود و ترکیب ناموجود در انتخاب غیرفعال می‌ماند. کالاهای ناموجود قابل افزودن نیستند.
- صفحه‌های `/login` و `/account` برای مشتریان ووکامرس فعال‌اند. فرانت‌اند رمز را فقط برای احراز هویت به وردپرس می‌فرستد و آن را ذخیره نمی‌کند؛ نشست ۱۲ ساعته در کوکی HttpOnly نگهداری می‌شود. فایل `wordpress/mu-plugins/khanechin-account.php` باید در `wp-content/mu-plugins` وردپرس نصب شود.
- ثبت‌نام از صفحهٔ `/register` باز است: حساب با ایمیل و رمز ساخته می‌شود و تا بازکردن پیوند تأییدِ ایمیلش، ورود بسته می‌ماند. بازیابی رمز از `/forgot` و `/reset` انجام می‌شود و پیوند تأیید از `/verify` دوباره قابل درخواست است. همهٔ این مسیرها روی `khanechin/v1` وردپرس سوارند، محدودسازی تلاش دارند و پاسخ‌شان وجود یا نبودن ایمیل را لو نمی‌دهد. برای ارسال ایمیل، وردپرس باید SMTP معتبر داشته باشد (مثلاً با افزونهٔ WP Mail SMTP) و گزینهٔ `khanechin_frontend_url` وردپرس به مبدأ HTTPS فرانت‌اند تنظیم شده باشد؛ بدون آن، ثبت‌نام با پیام روشن ناموفق می‌ماند.
- خواندن حساب از درخواست POST سرور به وردپرس انجام می‌شود؛ کش عمومی میزبان ممکن است پاسخ GET احراز‌شده را حتی با هدر `no-store` دوباره ارائه کند. خروج، نشست وردپرس را باطل می‌کند و فقط پس از تأیید پاسخ سرور، کوکی مرورگر را پاک می‌کند.
- اگر افزونهٔ LiteSpeed Cache روی وردپرس فعال است، گزینهٔ «Cache REST API» را خاموش و کش پیشین را پاک کنید. مسیر خصوصی `/wp-json/khanechin/v1/me` فقط POST را می‌پذیرد؛ GET قدیمی را در کش باقی نگذارید. در دموی عمومی این تنظیم اعمال و کش پاک شده است.
- صورت‌حساب، نشانی و تماس را اعتبارسنجی می‌کند، هزینهٔ تحویل حضوری رایگان تهران و مبلغ را دوباره از ووکامرس می‌خواند و تنها با روش پرداخت فعال در ووکامرس سفارش ثبت می‌کند. در پاسخ نامشخص، کاربر باید پیش از تلاش مجدد سفارش‌های حساب را بررسی کند.
- استان خریدار از فهرست کدهای معتبر ووکامرس ایران انتخاب می‌شود؛ نام فارسی استان نیز در API به همان کد تبدیل می‌شود. اگر افزونهٔ فروشگاه شما فهرست استان‌ها را تغییر می‌دهد، `lib/iran-states.js` را هم‌راستا نگه دارید.
- سوئیچ `STORE_CHECKOUT_ENABLED` پیش‌فرض خاموش است. در دموی عمومی، پس از پیکربندی تحویل حضوری و آزمون سفارش، برای ثبت سفارش آزمایشی روشن شده است. وقتی `ZIBAL_SANDBOX=true` باشد، فقط زیبال آزمایشی در فرانت‌اند قابل انتخاب و ثبت است؛ پرداخت در محل برای جلوگیری از برداشت سفارش واقعی بسته می‌ماند. `STORE_PICKUP_ADDRESS` نشانی محل تحویل را در صورت‌حساب نشان می‌دهد.
- واحد پول از پاسخ ووکامرس خوانده می‌شود و تبدیل پنهانی ریال به تومان انجام نمی‌شود؛ تنظیم واحد پول فروشگاه را پیش از عرضه بررسی کنید.
- برای زیبال، [افزونهٔ رسمی ووکامرس](https://github.com/zibalco/zibal-payment-gateway-for-woocommerce) را روی وردپرس نصب کنید و شناسهٔ پذیرنده را در تنظیمات آن بگذارید. مقدار `zibal` همراه با گزینهٔ Sandbox فقط برای تست است؛ برای دریافت پول واقعی به شناسهٔ پذیرندهٔ خودتان نیاز دارید. افزونه با مجوز GPL جدا از کد MIT این ریپو توزیع می‌شود. فایل `wordpress/mu-plugins/paasta-zibal-tls.php` را در `wp-content/mu-plugins` وردپرس بگذارید تا اعتبارسنجی TLS برای درخواست‌های زیبال روشن بماند.
- برای اینکه بازدیدکننده پس از ثبت سفارش به فرم پرداخت برسد، وردپرسِ متصل نباید در حالت WooCommerce «Coming soon» باشد؛ این حالت صفحهٔ `order-pay` را هم با صفحهٔ موقت جایگزین می‌کند. در دموی آزمایشی، Site visibility روی Live و روش `cod` در خود ووکامرس غیرفعال است تا از مسیر مستقیم وردپرس هم پرداخت در محلِ کالاهای نمایشی ثبت نشود. این تنظیمات را پیش از بازکردن سفارش در فروشگاه خود بررسی کنید.
- اگر میزبان وردپرس تابع PHP `mail()` ندارد، بازگشت از درگاه ممکن است هنگام ایمیل سفارش با خطای مهلک قطع شود، حتی اگر پرداخت ثبت شده باشد. فایل `wordpress/mu-plugins/paasta-sandbox-mail-guard.php` فقط در حالت `zibal` آزمایشی و در نبود `mail()` ارسال را با نتیجهٔ ناموفق متوقف می‌کند تا وضعیت پرداخت و صفحهٔ بازگشت آسیب نبینند؛ هیچ ایمیلی ارسال نمی‌شود. پیش از فروش واقعی SMTP معتبر و آزمون ایمیل‌های مدیر و مشتری را تنظیم کنید و این محافظ آزمایشی را بردارید.
- برای بازگشت از زیبال به صفحهٔ پیگیریِ فرانت‌اند، فایل `wordpress/mu-plugins/khanechin-return.php` را در `wp-content/mu-plugins` بگذارید و گزینهٔ `khanechin_frontend_url` وردپرس را به مبدأ HTTPS فرانت‌اند تنظیم کنید. صفحهٔ `/order/{id}` فقط در همان مرورگری که سفارش را ثبت کرده و کوکی HttpOnly سفارش را دارد، وضعیت را با کلید و ایمیل خریدار از Store API ووکامرس می‌خواند؛ پارامتر `wc_status` در URL اثبات پرداخت نیست. کوکی ۲۴ ساعت اعتبار دارد و کلید سفارش در URL بازگشت منتشر نمی‌شود. بدون کوکی، پیگیری از حساب ووکامرس انجام می‌شود.
- در این نمونه تنها تحویل حضوری رایگان تهران مجاز است و فرانت‌اند نرخ `local_pickup` صفر را پیش از سفارش بررسی می‌کند. محدوده و هزینه را برای فروشگاه خود تغییر دهید. این شش کالا ساختگی هستند و برای فروش عمومی واقعی مناسب نیستند.
- مسیر `/api/health` برای بررسی زنده‌بودن فرانت‌اند پاسخ ۲۰۴ می‌دهد؛ سلامت ووکامرس را جداگانه بررسی کنید.
- قبل از فروش واقعی، دامنه و TLS، تصاویر و مجوزشان، SEO محصولات، راهکار کش/تازه‌سازی، مالیات و هزینهٔ حمل را با فروشگاه خودتان آزمون کنید.

فونت «یکان‌بخ» در CSS اولویت دارد، اما به‌دلیل نیاز به بررسی مجوز بازنشر، فایل فونت در این نمونه بسته‌بندی نشده است. اگر مجوز استفاده دارید، فایل فونت را در `public/fonts/yekan-bakh.woff2` بگذارید و `@font-face` مناسب را به `app/style.css` اضافه کنید. در غیر این صورت فونت جایگزین سیستم نمایش داده می‌شود.

کد نمونه تحت مجوز MIT است. این نمونه از برند، تصاویر و چیدمان دیجی‌کالا کپی نمی‌کند و هویت مستقل «خانه‌چین» دارد. مجوز هر دارایی تصویری/فونت که خودتان اضافه می‌کنید باید بررسی شود.
