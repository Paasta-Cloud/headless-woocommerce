# خانه‌چین: نمونهٔ فروشگاه فارسی Headless WooCommerce

یک نمونهٔ مستقل و قابل‌تغییر از فروشگاه فارسی RTL با Next.js و WooCommerce Store API. این پروژه وابسته به کد داخلی پاستا نیست. صفحهٔ محصول، سبد، حساب و صورت‌حساب دارد. پرداخت در محل و درگاه زیبال را پشتیبانی می‌کند؛ زیبال در دموی فعلی فقط آزمایشی است.

دموی عمومی: [headless-woocommerce-demo.neda1.paasta.app](https://headless-woocommerce-demo.neda1.paasta.app). شش کالای نمایشی این دمو از یک نصب واقعی ووکامرس روی پاستا دریافت می‌شوند. قیمت‌ها در ووکامرس بر حسب ریال تنظیم شده‌اند. پرداخت آنلاین آزمایشی پول واقعی دریافت نمی‌کند؛ کالاها نیز نمایشی‌اند.

## راه‌اندازی

```bash
git clone https://github.com/Paasta-Cloud/headless-woocommerce.git
cd headless-woocommerce
npm install
npm run dev
```

فایل `.env` فقط مقدار غیرمحرمانهٔ `WOOCOMMERCE_URL=demo` دارد تا استقرار Git روی پاستا در حالت نمایشی کار کند. نام و قیمت‌های این حالت ساختگی‌اند. برای دریافت محصولات واقعی، `.env.example` را به `.env.local` کپی کنید و `WOOCOMMERCE_URL` را به نشانی HTTPS سایت وردپرس خود تنظیم کنید؛ در پاستا همین متغیر را در تنظیمات سرویس تغییر دهید. رمز و کلید را هرگز در `.env` عمومی ثبت نکنید. ویترین برای خواندن Store API عمومی به کلید مدیریتی نیاز ندارد.

برای استقرار روی پاستا، بعد از تنظیم نشانی ووکامرس در متغیر محیطی پروژه، از مسیر Git یا CLI استفاده کنید. ساخت پروژه و سرویس ممکن است هزینه داشته باشد؛ پلن و مبلغ را پیش از تأیید بررسی کنید. دستورهای پایه:

```bash
npm test
npm run build
paasta deploy --git https://github.com/Paasta-Cloud/headless-woocommerce.git --name my-store
```

## وضعیت قابلیت‌ها

- کاتالوگ، جست‌وجوی محلی و فیلتر دسته‌بندی کار می‌کنند. بدون تنظیم ووکامرس، سبد نمایشی و دادهٔ ساختگی نمایش داده می‌شود.
- در حالت اتصال، فهرست محصولات، تصویر، دسته‌بندی و قیمت از `/wp-json/wc/store/v1/products` دریافت می‌شود.
- هر کالا صفحهٔ مستقل دارد. در حالت اتصال، افزودن و تغییر تعداد کالا از Store API ووکامرس انجام می‌شود. Cart Token فقط در کوکی HttpOnly فرانت‌اند نگهداری می‌شود و سبد پس از بارگذاری دوباره بازیابی می‌شود. کالاهای متغیر و ناموجود در این نسخه قابل افزودن نیستند.
- حساب کاربری از مسیر امن `/my-account/` خود وردپرس باز می‌شود؛ فرانت‌اند گذرواژه را دریافت یا نگهداری نمی‌کند. ورود یکپارچهٔ داخل فرانت‌اند هنوز ارائه نمی‌شود.
- صورت‌حساب، نشانی و تماس را اعتبارسنجی می‌کند، هزینهٔ تحویل حضوری رایگان تهران و مبلغ را دوباره از ووکامرس می‌خواند و تنها با روش پرداخت فعال در ووکامرس سفارش ثبت می‌کند. در پاسخ نامشخص، کاربر باید پیش از تلاش مجدد سفارش‌های حساب را بررسی کند.
- استان خریدار از فهرست کدهای معتبر ووکامرس ایران انتخاب می‌شود؛ نام فارسی استان نیز در API به همان کد تبدیل می‌شود. اگر افزونهٔ فروشگاه شما فهرست استان‌ها را تغییر می‌دهد، `lib/iran-states.js` را هم‌راستا نگه دارید.
- سوئیچ `STORE_CHECKOUT_ENABLED` پیش‌فرض خاموش است. در دموی عمومی، پس از پیکربندی تحویل حضوری و آزمون سفارش، برای ثبت سفارش آزمایشی روشن شده است. وقتی `ZIBAL_SANDBOX=true` باشد، فقط زیبال آزمایشی در فرانت‌اند قابل انتخاب و ثبت است؛ پرداخت در محل برای جلوگیری از برداشت سفارش واقعی بسته می‌ماند. `STORE_PICKUP_ADDRESS` نشانی محل تحویل را در صورت‌حساب نشان می‌دهد.
- واحد پول از پاسخ ووکامرس خوانده می‌شود و تبدیل پنهانی ریال به تومان انجام نمی‌شود؛ تنظیم واحد پول فروشگاه را پیش از عرضه بررسی کنید.
- برای زیبال، [افزونهٔ رسمی ووکامرس](https://github.com/zibalco/zibal-payment-gateway-for-woocommerce) را روی وردپرس نصب کنید و شناسهٔ پذیرنده را در تنظیمات آن بگذارید. مقدار `zibal` همراه با گزینهٔ Sandbox فقط برای تست است؛ برای دریافت پول واقعی به شناسهٔ پذیرندهٔ خودتان نیاز دارید. افزونه با مجوز GPL جدا از کد MIT این ریپو توزیع می‌شود. فایل `wordpress/mu-plugins/paasta-zibal-tls.php` را در `wp-content/mu-plugins` وردپرس بگذارید تا اعتبارسنجی TLS برای درخواست‌های زیبال روشن بماند.
- برای اینکه بازدیدکننده پس از ثبت سفارش به فرم پرداخت برسد، وردپرسِ متصل نباید در حالت WooCommerce «Coming soon» باشد؛ این حالت صفحهٔ `order-pay` را هم با صفحهٔ موقت جایگزین می‌کند. در دموی آزمایشی، Site visibility روی Live و روش `cod` در خود ووکامرس غیرفعال است تا از مسیر مستقیم وردپرس هم پرداخت در محلِ کالاهای نمایشی ثبت نشود. این تنظیمات را پیش از بازکردن سفارش در فروشگاه خود بررسی کنید.
- در این نمونه تنها تحویل حضوری رایگان تهران مجاز است و فرانت‌اند نرخ `local_pickup` صفر را پیش از سفارش بررسی می‌کند. محدوده و هزینه را برای فروشگاه خود تغییر دهید. این شش کالا ساختگی هستند و برای فروش عمومی واقعی مناسب نیستند.
- مسیر `/api/health` برای بررسی زنده‌بودن فرانت‌اند پاسخ ۲۰۴ می‌دهد؛ سلامت ووکامرس را جداگانه بررسی کنید.
- قبل از فروش واقعی، دامنه و TLS، تصاویر و مجوزشان، SEO محصولات، راهکار کش/تازه‌سازی، مالیات و هزینهٔ حمل را با فروشگاه خودتان آزمون کنید.

فونت «یکان‌بخ» در CSS اولویت دارد، اما به‌دلیل نیاز به بررسی مجوز بازنشر، فایل فونت در این نمونه بسته‌بندی نشده است. اگر مجوز استفاده دارید، فایل فونت را در `public/fonts/yekan-bakh.woff2` بگذارید و `@font-face` مناسب را به `app/style.css` اضافه کنید. در غیر این صورت فونت جایگزین سیستم نمایش داده می‌شود.

کد نمونه تحت مجوز MIT است. این نمونه از برند، تصاویر و چیدمان دیجی‌کالا کپی نمی‌کند و هویت مستقل «خانه‌چین» دارد. مجوز هر دارایی تصویری/فونت که خودتان اضافه می‌کنید باید بررسی شود.
